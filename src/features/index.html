Features

Everything Venora does today.

This is the feature set of Venora {{ venoraVersion }}. If something isn't on this page, it isn't in Venora yet. The roadmap says what's planned.

01 Plugin manager

A Plugins page inside Fermo's settings.

Each plugin has a card with its name, version, author and description. Imported plugins are marked as imported.

Install from a ZIP

Choose Add plugin and pick a ZIP with plugin.json and its entry script, at the root or inside one folder. Every part is validated before anything is stored.

Enable and disable

Switch optional plugins on and off. A greyed-out, checked box marks a required bundled plugin. Imported plugins can never make themselves required.

Permissions, in plain words

See what each plugin declared, with a description of every permission. Sensitive ones need your confirmation at install and at every update that declares them.

Plugin settings

Plugins declare settings, and Venora draws the dialog: on/off switches, text, numbers with limits, and choices from a list. Only you can change them, and a running plugin can subscribe to hear when you do.

Manual updates

Add a newer ZIP of an installed plugin. Venora compares versions using semantic versioning, shows the release notes, and keeps the plugin's settings and data.

Clean uninstall

Uninstalling an imported plugin stops it and deletes its files, enabled state, settings and stored data. Nothing of it remains.

Release notes

Plugins can ship a changelog of breaking changes, new features, improvements and bug fixes. Update prompts show the new version's notes, and the info dialog shows the whole history.

Compatibility checks

A plugin can require a Plugin API version and a minimum Venora version. Incompatible plugins are refused at install, and skipped at load with the reason on their card.

Author information

A plugin's author, or list of maintainers, is shown as “By …” on its card. Like every plugin-provided string, it is shown as text, never as HTML.

02 At a glance

Every card says what its plugin is doing.

Plugins start when you open a channel and stop when you leave. If one fails, its card says why, and the others keep running.

  • Running in sandbox
  • Failed to run: reason
  • Not compatible: reason
  • Not running: safe mode is on
  • Stopped after repeated problems on this page.
  • Required · Imported

03 Safe mode & recovery

A way out that no plugin can cover up.

Plugin CSS can restyle Fermo's page, including its settings. So Venora keeps its controls somewhere plugins can't reach.

Safe mode

  • Stops every imported plugin and removes its CSS, without a reload
  • Bundled plugins keep running
  • A switch on the Plugins page and in the toolbar menu

The Venora toolbar menu

  • Lives outside Fermo's page, so plugin CSS doesn't apply to it
  • Enable or disable plugins, and uninstall imported ones
  • Open Fermo tabs apply each change immediately

04 Runtime

What every plugin runs inside.

The same runtime applies to bundled and imported plugins alike. The security page covers each part in depth.

Sandbox

A dedicated worker in a sandboxed frame: no DOM, no network, no extension APIs.

Capabilities

Privileged work happens only through a fixed set of permission-checked capabilities.

Token protection

Plugins are never sent your Fermo session token. A guard checks every message.

Private storage

Each plugin gets its own key–value store of up to 1 MiB, kept across reloads and updates.

Events

Plugins can subscribe to setting changes and to mentions appearing on the page.

Plugin CSS

A plugin with ui can restyle Fermo. CSS that loads resources or writes text isn't applied.

Resource limits

Per-plugin request, event and message limits, timeouts, and caps on storage and install size.

Watchdog

Stops plugins that stop responding. A plugin that keeps misbehaving stays off until you reload.
